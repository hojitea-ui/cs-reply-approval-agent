# 고객 문의 자동 답변 · 사람 승인(HITL) 에이전트

쇼핑몰 고객 문의에 AI가 답변 초안을 만들고, **위험한 건만 발송 직전에 멈춰 사람의 승인을 받는** LangGraph 에이전트와 Streamlit 웹 데모입니다.
평범한 문의는 사람 없이 끝까지 자동 발송되고, 멈춘 건은 SQLite 체크포인터에 보관되어 앱을 껐다 켜도 이어서 처리할 수 있습니다.

## 실행 방법

```bash
pip install -r requirements.txt
streamlit run app.py
```

브라우저에서 사이드바의 **샘플 30건 한꺼번에 접수**를 누르면 됩니다. API 키는 필요 없습니다.

| 확인하고 싶은 것 | 명령 |
|---|---|
| 웹 데모 | `streamlit run app.py` |
| 중단/재개/재시작 후 보관 테스트 | `python test_agent.py` |
| 멈춤 기준별 개입률·놓침·헛멈춤 비교표 | `python evaluate.py` (결과는 `eval_result.md`) |

(선택) `ANTHROPIC_API_KEY` 환경변수를 설정하면 분류 단계를 LLM이 맡습니다. 실패하면 규칙 기반으로 자동 대체되며, 평가 스크립트는 재현성을 위해 항상 규칙 기반만 씁니다. 키는 코드/저장소에 넣지 않습니다.

## 파이프라인

```
접수 → draft(분류·규정 검색·초안) → check(멈춤 기준) ─ 안 걸림 → send (자동 발송)
                                          └ 걸림 → review ← interrupt: 여기서 멈춤
                                                     ├ 승인 / 수정 후 승인 → send
                                                     ├ 반려(사유 필수)      → reject
                                                     └ 다시 판정(지시, 최대 2회) → draft → check → review
```

- 고객에게 나가는 동작은 `send` 노드 하나뿐이고 `review` 와 분리되어 있습니다. 재개 시 멈춘 단계가 처음부터 다시 실행되어도 중복 발송이 없습니다.
- 요청 한 건 = `thread_id` 하나. 대기 건이 여러 개여도 섞이지 않습니다.
- 다음 실행 단계(`next`)가 `review` 이면 승인 대기 건입니다.

## 멈춤 기준 (하나라도 걸리면 사람에게)

| 코드 | 조건 | 대비하는 위험 |
|---|---|---|
| `low_confidence` | 분류 확신도 < 0.7 | 질문을 잘못 이해한 답변 |
| `no_citation` | 근거 규정을 인용하지 못함 | 근거 없는 답변·잘못된 약속 |
| `risk_words` | 소비자원, 신고, 고소, 변호사, 법적, 언론, 병원, 다쳤, 알레르기, 화상 포함 | 법적 분쟁·안전 사고·공개 항의 |

다시 판정으로 만든 답변은 기준과 무관하게 항상 사람이 한 번 더 봅니다. 기준을 정한 이유와 검증은 [REPORT.md](REPORT.md)에 있습니다.

## 파일

| 파일 | 역할 |

| `policy.py` | 규정집, 분류 키워드, 위험 표현 목록 |
| `samples.py` | 라벨링된 문의 30건 |
| `evaluate.py` | 기준별 비교표 생성 |
| `app.py` | Streamlit 웹 데모 |
| `test_agent.py` | 동작 검증 테스트 |
